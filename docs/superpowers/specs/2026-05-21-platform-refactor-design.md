# 前后端完全解耦+重构设计方案

**日期**: 2026-05-21
**版本**: v1.0
**状态**: 已批准

## 一、背景与目标

当前系统存在以下问题：
1. 全平台API请求500 - 端口配置不一致
2. APK上传无法正确解析包名和版本
3. 用例/脚本管理强制要求先选择项目，用户体验差

本设计方案旨在：
- 统一端口配置，使用环境变量管理
- 增强APK解析能力，支持多种解析方法
- 优化用例/脚本管理，提供全局新增入口

## 二、架构设计

### 2.1 端口配置管理

**方案**: 使用环境变量 + `.env` 文件

```
# frontend/.env
VITE_API_URL=http://localhost:9000

# backend/.env
BACKEND_PORT=9000
```

**实施要点**:
- `.env` 文件不提交到版本控制
- 前端使用 `VITE_` 前缀的环境变量
- 后端通过 `python-dotenv` 读取配置
- 统一使用 `9000` 作为默认服务端口

### 2.2 APK解析逻辑

**优先级**: aapt2 > aapt > unzip/AndroidManifest.xml

```
流程:
1. 查找系统中的 aapt2 工具
2. 找不到则查找 aapt
3. 都找不到则使用 unzip 直接解析 AndroidManifest.xml
4. 任一方法成功即停止
```

**工具搜索路径** (Windows):
```
- %ANDROID_HOME%/build-tools/*/aapt2.exe
- %ANDROID_SDK_ROOT%/build-tools/*/aapt2.exe
- C:\Users\{username}\AppData\Local\Android\Sdk\build-tools\*\aapt2.exe
- PATH 中可直接访问的 aapt2
```

### 2.3 用例/脚本强制关联项目

```
创建用例/脚本时：
- 项目选择器必填，未选择时禁用保存按钮
- 保存时校验 project_id 存在
- 无项目时显示引导创建项目的提示
```

## 三、API设计

### 3.1 全局API (项目无关)

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/projects` | GET | 项目列表 |
| `/api/projects` | POST | 创建项目 |
| `/api/apks` | GET | APK列表（支持?project_id=过滤） |
| `/api/apks` | POST | 上传APK |
| `/api/keywords` | GET | 关键字列表 |

### 3.2 项目相关API

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/projects/{id}` | GET/PUT/DELETE | 项目详情/更新/删除 |
| `/api/projects/{id}/cases` | GET/POST | 项目下的用例 |
| `/api/projects/{id}/scripts` | GET/POST | 项目下的脚本 |
| `/api/projects/{id}/pages` | GET/POST | 项目下的页面 |
| `/api/projects/{id}/stats` | GET | 项目统计 |
| `/api/projects/{id}/custom-keywords` | GET/POST | 项目自定义关键字 |

## 六、实施步骤

### Step 1: 环境配置
- 创建 `frontend/.env` 文件
- 创建 `backend/.env` 文件
- 修改 `vite.config.js` 使用环境变量
- 修改 `config.py` 支持环境变量

### Step 2: 后端端口配置
- 修改 `config.py` 从环境变量读取端口
- 修改后端启动命令使用9000端口

### Step 3: APK解析增强
- 实现 `find_aapt_tools()` 查找aapt2/aapt
- 实现多方法fallback解析逻辑
- 优化错误处理和日志

### Step 4: 数据库迁移
- 为 `scripts` 表添加 `project_id` 字段
- 为 `test_cases` 表添加 `project_id` 字段
- 确保向后兼容

### Step 5: API适配
- 修改用例API支持全局查询和项目过滤
- 修改脚本API支持全局查询和项目过滤
- 添加项目不存在时的友好提示

### Step 6: 前端UI重构
- 用例管理页面：添加全局新增入口
- 脚本管理页面：添加全局新增入口
- 项目选择器必填校验

## 七、验收标准

1. **端口配置**: 前端能通过环境变量正确代理到后端
2. **APK解析**: 上传鹿客管家APP能正确显示包名 `com.lockin.loock`
3. **用例管理**: 无项目时也可点击新建用例，创建时必须选择项目
4. **脚本管理**: 无项目时也可点击上传脚本，创建时必须选择项目
5. **API稳定性**: 所有API正常返回，无500错误

## 八、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 数据库迁移失败 | 数据丢失 | 提前备份，创建迁移脚本 |
| aapt工具路径不一致 | APK解析失败 | 多路径搜索 + fallback方案 |
| 环境变量配置复杂 | 开发体验差 | 提供 `.env.example` 模板 |
